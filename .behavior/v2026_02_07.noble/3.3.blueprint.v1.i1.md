# blueprint v1

## summary

swap `node:crypto` → `@noble/hashes` to make hash-fns isomorphic. drop md5. make all functions sync. bump to v3.0.0.

## contracts used

| contract | source | role |
|----------|--------|------|
| `sha256(data: Uint8Array): Uint8Array` | `@noble/hashes/sha2` | sha256 digest |
| `shake256(data: Uint8Array, opts: { dkLen }): Uint8Array` | `@noble/hashes/sha3` | variable-length shake256 digest |
| `bytesToHex(bytes: Uint8Array): string` | `@noble/hashes/utils` | byte array → hex string |
| `TextEncoder.encode(str): Uint8Array` | web platform (universal) | string → utf-8 bytes |
| `AsOfGlossary<string, 'hash-fns'>` | `domain-glossaries` | branded type for Hash |
| `withAssure(guard): guard & { assure }` | `type-fns` | type guard with fail-fast `.assure()` |

## test coverage

### unit tests (sync, no remote boundaries)

**asHashSha256.test.ts** — covers usecase.1
- known test vector: `'hello world'` → `b94d27b9934d3e08a52e52d7da7dabfac484efe37a5380ee9088f7ace2efcde9`
- known test vector: `''` → `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`
- unicode input: `'你好世界'` → valid 64-char hex
- determinism: same input → same output
- uniqueness: different inputs → different outputs
- sync assertion: return type is `string`, not `Promise`

**asHashShake256.test.ts** — covers usecase.2
- default 32 bytes → 64-char hex
- custom 16 bytes → 32-char hex
- custom 64 bytes → 128-char hex
- determinism: same input + options → same output
- uniqueness: different inputs → different outputs
- sync assertion: return type is `string`, not `Promise`

**isHashSha256.test.ts** — covers usecase.3
- valid sha256 hex → returns true
- invalid string → returns false
- `.assure()` on invalid → throws with `assure.rejection` message

### acceptance tests

usecase.4 (isomorphic runtime compat) is proven by the dep chain itself — `@noble/hashes` is pure js with zero native deps. no runtime-specific test needed; the unit tests themselves prove it works.

usecase.5 (removed exports) is proven at compile time — `npm run test:types` will fail if any code imports the removed symbols.

usecase.6 (v3 metadata) is verified by `package.json` inspection.

## key decisions

1. **`bytesToHex` from noble** — noble ships its own hex encoder. no need to roll our own `Array.from(...).map(...).join('')` pattern. simpler, tested, consistent.

2. **`TextEncoder` for string → bytes** — already used in the v1 codebase. universal across all js runtimes. no `Buffer` dependency.

3. **`dkLen` vs `outputLength`** — noble uses `dkLen` (derived key length) for shake256's variable output, not node's `outputLength`. our public api stays `{ bytes }` and maps internally.

4. **exact version pin** — `@noble/hashes` pinned to `2.0.1` (not `^2.0.1`) per practices.
