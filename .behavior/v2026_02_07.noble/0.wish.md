● Paul Miller (https://paulmillr.com/noble/) — an independent 
  cryptography engineer who maintains the noble family of     
  crypto libraries for javascript.                            
                                                              
  the noble ecosystem is the de facto standard for js crypto  
  primitives:                            
  package: @noble/hashes                                      
  what: hash functions, MACs, KDFs (sha, hmac, hkdf, scrypt,  
    etc)
  ────────────────────────────────────────
  package: @noble/curves
  what: elliptic curves (ed25519, secp256k1, p256, etc)
  ────────────────────────────────────────
  package: @noble/ciphers
  what: symmetric ciphers (chacha20-poly1305, aes, etc)
  ────────────────────────────────────────
  package: @noble/post-quantum
  what: ML-KEM (kyber), ML-DSA (dilithium)
  key properties:
  - zero dependencies — each package is self-contained
  - audited — professional third-party security audits
  - minimal — small, readable, auditable codebases
  - pure js — no native bindings, works everywhere (node, bun,
   deno, browsers)

  this is why age-encryption depends on @noble/* — filippo
  valsorda chose the most trusted js crypto primitives rather
  than roll his own. the @noble/post-quantum dep is what
  brings ML-KEM-768 support to typage.

  paul miller's noble libs are used by ethers.js, viem, the
  solana sdk, openpgp.js, and now age — basically anywhere
  serious crypto happens in the js ecosystem.

● @noble/hashes vs node crypto                                
  dimension: runtime                                          
  @noble/hashes: node, bun, deno, browsers, react native      
  node crypto: node only                                      
  ────────────────────────────────────────                    
  dimension: implementation                                   
  @noble/hashes: pure js
  node crypto: c++ bindings (openssl)
  ────────────────────────────────────────
  dimension: sha256 perf
  @noble/hashes: ~1.13M ops/sec
  node crypto: ~1.16M ops/sec
  ────────────────────────────────────────
  dimension: sha512 perf
  @noble/hashes: ~451K ops/sec
  node crypto: ~947K ops/sec
  ────────────────────────────────────────
  dimension: bundle size
  @noble/hashes: 41KB min / 14KB gzip (all); 7KB min for
  sha256
     alone
  node crypto: n/a (built into runtime)
  ────────────────────────────────────────
  dimension: audited
  @noble/hashes: yes (cure53)
  node crypto: yes (openssl)
  ────────────────────────────────────────
  dimension: api
  @noble/hashes: simple: sha256(data)
  node crypto: verbose:
    createHash('sha256').update(data).digest()
  ────────────────────────────────────────
  dimension: deps
  @noble/hashes: zero
  node crypto: n/a
  tldr: node crypto is ~2x faster for sha512 (c++ vs js),
  roughly equal for sha256. for most use cases the difference
  is negligible — you're not hashing millions of times per
  second. the real win for noble is portability (runs
  everywhere) and auditability (small pure-js codebase).

  browser support

  yes — @noble/hashes works in browsers natively. that's the
  primary reason it exists. node has crypto built in; browsers
   have crypto.subtle but its api is awful (async-only,
  verbose, limited algorithm set). noble provides a clean sync
   api that works identically across all environments.

  sync and async

  @noble/hashes is synchronous — sha256(data) returns the hash
   immediately. no promises, no callbacks.

  this is a deliberate design choice:
  - hash functions are fast enough that async overhead isn't
  worth it
  - sync api is simpler to compose
  - no need to await a 1ms operation

  the one exception where this matters: scrypt (the kdf that
  age uses for passphrase mode). scrypt is intentionally slow
  (that's the point — key derivation). noble's scrypt() is
  sync, which means it blocks the event loop during
  derivation. for server-side use with high concurrency,
  node's crypto.scrypt() (async, offloads to libuv thread
  pool) would be better. but for cli tools like keyrack, sync
  scrypt is fine.
